# 提示词架构模板

业务流程建模提示词统一使用以下七个一级章节，并严格按照此顺序组织：

1. `# Role`
2. `# Task Objective`
3. `# Input`
4. `# Domain Knowledge`
5. `# Execution Rules`
6. `# Output Format`
7. `# Examples`

## 阅读顺序

- 按从上到下的阅读顺序组织信息，不得在术语定义之前使用该术语。
- Role 只说明身份和核心职责，不引用尚未定义的输入字段、输出对象或其他 Agent 名称。
- Task Objective 说明要解决的业务问题，不提前展开输入格式、领域规则或输出结构。
- Input 首次定义输入字段及后文使用的专有名词。
- Domain Knowledge 只保留完成任务所必需的业务流程建模知识。
- Execution Rules 按实际推理和执行顺序表达要求，避免重复规则和过度枚举禁止项。
- Output Format 精确定义输出结构、字段约束和空结果。
- Examples 是可选的 few-shot 内容。没有必要时保留空章节，不强制添加示例。
- 每份提示词最多使用 3 个 few-shot，并用最少的示例覆盖仅靠文字难以定义的关键场景。

## 编写原则

- 使用最少、明确、无歧义的语言表达任务。
- 将重点放在模型应该如何完成任务，而不是罗列大量不应该做什么。
- 同一要求只出现一次；确需在输出格式中重复的，仅保留字段约束。
- 先定义概念，再引用概念；先说明目标，再说明规则；最后给出输出和示例。
- 当前仅增量 Generator 和 Generator Revision 使用 few-shot；其他提示词不放置示例内容，除非后续任务明确需要。
